# Native x86-64 layout and addressing: Linux

The second x86-64 pass targets varints, fannkuch and CRC-32. It writes blocks
that only return or fail after the epilogue, inverts branches that would jump
over them, and folds scaled array indexes into memory operands. On the same
host as the [first pass](2026-10-26-x64-native-performance.md), the unchanged
release gate now passes on Linux x86-64 at **1.283× C** (ceiling 1.5;
1.880× before the first pass). The
[walkthrough](../../docs/history/x64-native-performance.md#second-pass-layout-and-addressing)
describes the changes; [TL-086](../../docs/tooling-backlog.md#tl-086-x86-64-hot-paths-jumped-around-inline-failure-blocks)
records the gap and validation.

## Host

The same Linux x86-64 VM (Intel Xeon @ 2.10 GHz, model 207, four logical
CPUs, GCC 13.3.0, GNU Binutils 2.42). Before is commit `bfc8395`; after is
this change's refreshed seed. Runtime, std and package sources are unchanged
between them.

By best samples the tool reports 1.420× → 1.334×.

The three apparent slowdowns do not reproduce as code regressions. Assembling
the same compiler outputs by hand and linking them with one runtime object
(eleven interleaved rounds) gives:

| Workload | Before | After | Before, mitigated | After, mitigated |
| --- | ---: | ---: | ---: | ---: |
| wordfreq | 302 ms | 288 ms | 293 ms | 292 ms |
| knucleotide | 314 ms | 389 ms | 408 ms | 326 ms |
| nbody | 445 ms | 416 ms | 450 ms | 398 ms |

"Mitigated" assembles with `-Wa,-mbranches-within-32B-boundaries`.
knucleotide reverses direction under the mitigation alone, so branch
placement (TL-085), not the generated instructions, decides these rows.
varints shows the same effect from the other side: its after code measures
199–237 ms through `vela build` depending only on where it lands, and 170 ms
mitigated (229 ms before).

## Release gate

The unchanged `bench/run.py --require-native-parity --runs 5` gate
[passes at 1.283×](2026-10-26-x64-layout-release-parity.json) with every
output matched and the native-built compiler faster (check 0.268 s versus
0.351 s; C emission 0.632 s versus 0.871 s). Given TL-085, a single gate run
on this CPU can move by more than the change in any one workload; the pass is
reported as measured, not as a stable margin.

## Validation

- Both fixed points pass after the seed refresh (1,982,784 x86-64 assembly
  lines).
- Complete C and native suites each pass 314 of 316 checks. The x86-64
  assembly snapshot changed as intended (the base case moves after the
  epilogue and three `jle`/`jmp` pairs become `jg`); it was traced against
  the source, assembles, and passes once updated. The remaining failure is the
  known M24 query-latency gate (VAL-007).
- `VELA_OPT=0` native selection: 255/255.
- M27 with gdb and the deep compiler panic (`VELA_M27_DEBUGGER=1
  VELA_M27_COMPILER_PANIC=1`) passes on both backends.
- `tests/run/x64_layout.vl` covers a checked store as a function's last
  statement, early returns from nested loops, `Err` inside loops, Bool and
  NaN-reaching Float branches whose false path returns, and consecutive
  checks. Its helpers are kept above the inlining limit where the shape needs
  its own return. A first version of the layout misplaced the block a skipped
  branch falls into (it dropped nbody's last store); this fixture fails on
  that version and passes on the corrected one.
